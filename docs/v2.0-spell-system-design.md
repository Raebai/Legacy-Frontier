# Spell System & Class Tree — Design

**Date:** 2026-07-12 · **Branch:** `v2.0-tower` · **Status:** foundation built, tree designed

The combat "moat #2" (after the AI-NPC hub): a **data-driven spell/class tree** that
delivers Frieren / isekai / divine **spectacle** — massive magic circles, screen-crossing
beams, pillars of holy light — while staying **mobile-first** (few in-combat inputs; the
tree is a *loadout selector*, not 30 always-on keys).

North-star feel: the AVM-shorts / Frieren "a huge sigil blooms and a beam erases the
screen" moment. See [[project_v2_combat_usp_stickfigure]] and the marketing content idea
([[project_ai_stickmen_battle_content]] — bot-vs-bot spell battles as clips).

---

## 1. Architecture (data-driven, shipped this session)

Three layers, mirroring the project's `NPCData` / `TowerDef` ethos:

- **`SpellDef`** (Resource) — one spell as pure data: `kind` (BEAM / DIVINE_RAY / NOVA /
  METEOR / …), element/colour, `mp_cost`, `cooldown`, `damage`, geometry (length/width/
  radius/reach), flavour text. `.tres`-authorable.
- **`SpellCaster`** (static dispatcher) — the ONE seam from data → spectacle. `cast(spell,
  arena, origin, target, colour)` matches `kind` to a spectacle scene (`BeamSpell`,
  `DivineRay`, `EnergyNova`, …). New `kind` = one match arm + one scene; nothing else moves.
- **`SpellLibrary`** (curated list) / future `data/spells/*.tres` — the equippable spells.

Spectacle scenes (reusable, procedural, no assets):
- **`MagicCircle`** — animated arcane sigil (counter-rotating runic rings, glyph ticks,
  inscribed hexagram, white-hot core). `appear()` / `vanish()`. The shared "a sigil
  materialises" primitive for every spectacle.
- **`BeamSpell`** — the Zoltraak sigil-beam (charge telegraph → screen-crossing beam →
  fade). Line-damage.
- **`DivineRay`** — the holy pillar (sky sigil + ground telegraph → column crashes down).
  Radius-damage.

**Adding a spell:** author a `SpellDef` (code or `.tres`). If its `kind` already exists,
zero new code. If it needs a new spectacle, add one Node2D scene (mirror `EnergyNova`) +
one `SpellCaster` match arm.

## 2. Resource & input model (mobile-first)

- **MP (mana):** gates the big signature spells. Regenerates (~20/s) so ultimates are a
  paced resource, not spam. Basic abilities stay cooldown-gated (unchanged).
- **The signature slot:** ONE Ultimate button (`G` on desktop; one on-screen button on
  mobile) casts the *equipped* signature. Cycle the equipped signature with `V` (a loadout
  selector — becomes a pre-fight/hub choice on mobile, not an in-combat key).
- **HP/MP bars** float over every fighter (`CharacterBars`): HP for all, +MP for the hero.
- The **tree is progression/customisation**, resolved *outside* combat — so the in-combat
  input set stays the settled ~10 actions. This is the answer to the "10 actions won't fit
  touch" constraint: depth lives in the loadout, not the button count.

## 3. Class → Subclass → Blend tree

Three **base affinities**. Each has **subclasses** (specialisations). **Blends** fuse two
affinities into a hybrid with a unique fusion signature. (Progression/unlock UI = later.)

| Base | Fantasy | Subclasses |
|------|---------|-----------|
| **Arcanist** (arcane) | Frieren-style pure mage; sigils & beams | Sorcerer (Zoltraak), Astromancer (sky/meteors), Chronomancer (time) |
| **Blade** (shadow/steel) | in-and-out assassin | Shadowdancer (blink-slice), Bladestorm (whirlwind) |
| **Cleric** (divine) | holy smiter/support | Templar (judgment rays), Inquisitor (holy fire/chains) |

**Blends** (pick two affinities → fusion subclass + signature):

| Blend | = | Signature idea |
|-------|---|----------------|
| **Spellblade** | Arcanist + Blade | *Phase Lance* — blink to the mark, then a point-blank beam |
| **Paladin** | Blade + Cleric | *Radiant Charge* — a divine dash that smites along its trail |
| **Runepriest** | Arcanist + Cleric | *Astral Judgment* — a sky sigil fires a slowly-sweeping arcane-holy beam |

## 4. Unique spell catalogue (the "cool ideas")

`kind` in brackets. ✅ = built + castable this session. ○ = designed, not built (reserve the
`SpellDef.Kind` value + a spectacle scene).

**Arcanist**
- ✅ **Zoltraak · Arcane Beam** `[BEAM]` — the iconic screen-crossing mana lance.
- ✅ **Frostpiercer** `[BEAM]` — long, thin spear of absolute cold; pierces a rank.
- ✅ **Infernal Lance** `[BEAM]` — fat, roaring fire beam; short reach, brutal width.
- ○ **Meteor Sigil** `[METEOR]` — a sky circle rains a cluster of meteors on an area.
- ○ **Prismatic Barrage** `[BEAM×n]` — a sigil fans out several thin beams.
- ○ **Gravity Well** `[AOE]` — a sigil that sucks fighters in, then implodes.
- ○ **Grand Sigil "Overload"** `[BEAM]` — long charge, whole-screen-width annihilation beam.

**Cleric (Divine)**
- ✅ **Judgment · Divine Ray** `[DIVINE_RAY]` — a pillar of holy light on the marked ground.
- ✅ **Heaven's Verdict** `[DIVINE_RAY]` — vast circle, cataclysmic wide-footprint ray.
- ○ **Sanctuary** `[AOE-heal]` — a holy circle that heals allies / cleanses.
- ○ **Divine Chains** `[LINE-root]` — holy chains erupt to root a line of enemies.
- ○ **Consecration** `[GROUND]` — burning holy ground that ticks over time.

**Blade**
- ○ **Umbral Ray** `[BEAM]` — a dark, silent beam from a shadow sigil.
- ○ **Shadow Chain** `[BLINK-combo]` — blink between marked targets, slicing each.
- ○ **Bladestorm** `[NOVA]` — self-centred whirlwind of thrown blades.

**Blends / summons (the isekai flourish)**
- ○ **Guardian Summon** `[SUMMON]` — a magic circle summons a construct (the "magic-circle
  bear/golem" from the north-star) that fights for a duration.
- ○ **Astral Judgment** `[SWEEP-BEAM]` — a sky sigil fires a rotating beam that sweeps an arc.
- ○ **Phase Lance** `[BLINK+BEAM]` — blink to the target, then a point-blank beam.
- ○ **Radiant Charge** `[DASH+SMITE]` — a divine dash leaving a smiting trail.

## 5. Built this session vs designed

- **Built + verified:** `MagicCircle`, `BeamSpell`, `DivineRay`; `SpellDef` / `SpellCaster`
  / `SpellLibrary`; MP resource + Ultimate (`G`) / cycle (`V`) input; `CharacterBars`
  HP/MP; hotbar signature slot; 5 castable signatures (3 beams + 2 divine rays).
- **Designed, not built:** everything marked ○ above; the class/subclass/blend *progression
  + unlock UI*; per-class slot-spell loadouts (today only the signature slot is data-driven,
  the other slots still come from `CLASS_CONFIG`); moving `SpellLibrary` → `data/spells/*.tres`.
