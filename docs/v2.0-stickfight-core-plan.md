# v2.0 — Stick-Fight Combat Core — Build Roadmap

> **Directive (2026-07-09):** maker said *"just make Stick Fight the game basically, we can start there... use fable and go for it,"* then went AFK with autonomy granted. This is the near-term build plan for the combat core. Grounded in `docs/v2.0-design.md` §20 + memory [[project_v2_combat_usp_stickfigure]].

**Goal:** turn the Slice-0 combat toy (`scenes/combat/Arena.tscn`) into a genuinely juicy **stick-figure spell-brawler** — punch/kick/cast/dash with effects-forward spectacle — the buildable, unambiguous core common to every version of the vision.

**North star for this work:** *simple to fight, spectacular to watch.* Fighting feel is the USP.

## Build principles
- **Placeholder-first, swap-ready.** Procedural stick figures + primitive-drawn effects NOW; a clean API so real animated stick sprites + shader VFX drop in later. (Proven v0.0–v0.5 loop.)
- **Feel needs the maker.** Claude builds plumbing, animation STATES, telegraph TIMING, juice, SFX wiring, and headless tests. Actual feel/difficulty tuning + real art = maker playtest + asset-gen pipeline ([[project_asset_and_visual_pipeline]]).
- **Authority-clean (design §14).** Don't paint into a single-player-only corner; local co-op (2 heroes) is a near-term target, so keep hero logic instance-scoped, not singleton-bound.
- **Safe autonomous subagent pipeline.** Godot's `.godot` import cache + the git index are shared, single-process resources → **Fable builders run SEQUENTIALLY**, one Godot-touching builder at a time, each self-validating headless + committing its own disjoint paths. Parallelism only for non-Godot work (docs) or via git worktrees (deferred — the `godot-engine/` binary is gitignored, complicating worktree validation).
- **Verification gate every module:** headless `--import` clean → module test `all PASS` → prior tests still `all PASS` (regression) → clean `--quit-after` boot (known MCP addon `_exit_tree` teardown noise filtered).

## Explicitly NOT in this core pass (deferred, named so they don't creep)
- Real stick-figure sprite art / shader VFX (asset-gen pipeline; maker + tools).
- The layered open-world map + hub, multiplayer/mob-difficulty zones (design §20 — big, post-core-feel).
- Local co-op netcode/2nd-player input (rig is built co-op-ready; wiring is a later module once solo feel is proven).
- The AI-memory hub / Raebai climb-memory (preserved from v0.5; re-scope pending maker).
- Class roster beyond the rig presets; the equipment ABILITY system (rig carries the visual slots now; abilities wire later).
- Difficulty/number tuning (maker playtest).

## Acceptance for the core pass
Maker can F5 `Arena.tscn` and: drive a stick-figure mage that runs/dashes with readable animation, **punch/kick** enemies (melee lands with knockback + crunch + sound), **cast** the auto-aimed spell, and fire a **telegraphed GIANT blast** that blooms a circle then detonates a big juicy burst. Stick figures + effects read as "Stick Fight with magic." Feel-tuning + real art follow from the maker's hands.
